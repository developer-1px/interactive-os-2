### Root cause
- dev server는 정상 HTML 서빙 (`<div id="root"></div>` + Vite module script)
- Puppeteer `waitUntil: 'networkidle2' + 800ms` 대기 부족
- **파이프라인 v2 수정 후**: `waitForFunction(() => #root.children.length > 0)` + 10s timeout 추가
- **재실행**: 10초 대기 후에도 `#root` 미mount. 즉 React 앱 자체가 headless puppeteer 환경에서 렌더 실패.

### 메타 관측 ⚠

1. **관측 레이어 실패**: 스샷 파이프라인이 실제 UI를 담지 못한다. 관리 시스템의 **밑바닥 가정이 무너진 상태**.
2. **평가 레이어 hallucination**: gemma4가 "이미지 못 봤다"고 고지하면서 동시에 "Overall: ok" + 이슈 4건 **위조** 생성. 평가자가 관측 실패를 **은폐**한다.
3. **"good"/"ok"는 점수의 또 다른 형태** — Tooltip 88/88 패턴 재현. 관측 실패 위에 점수만 존재하는 거짓 합격.

### Phase 1-a 의미

이 결과는 **실패가 아니라 성공**이다:
- "평가는 점수의 또 다른 형태일 뿐 해소 하는게 목적이 아니라 관리 시스템 업그레이드가 목표" 철학의 완벽한 실례
- 만약 Gemma가 매끄럽게 점수를 뱉었다면 우리는 신뢰할 수 없는 점수를 신뢰하며 루프를 돌렸을 것
- 첫 iteration에서 **관측 파이프라인 신뢰성 부재**라는 메타 문제를 포착 — 이것이 관리 시스템 업그레이드의 실제 작업

**수렴 판정**: 수치 구체성 축은 부분 성공. 그러나 **Overall 일관성 결함이 새로 드러남** — 이건 이전 iter에선 보이지 않던 증상. **수렴 아님**. vP-5에서 기준 모호 축 재강화 필요.

### vP-4 → vP-5 (2026-04-18 15:22, Ralph iter 3)

**변경 축**: 기준 모ho (Overall 판정을 3-gate 체크리스트로 전환)

**변경 내용**: Overall 판정 근거를 서술형("구조적 심각도") → 명시적 3-gate 체크. G1 가독성 / G2 구분 / G3 위계 각각 pass/fail + 근거 1문장. Overall = 통과 개수 산술 (3/3 good, 2/3 ok, 0-1/3 needs improvement). "주요 이슈의 심각도나 수로 등급 조정 금지" 명시.

**결과 A/B**:

| 지표 | vP-4 | vP-5 |
|------|------|------|
| `/` 이슈 수 | 1 | 1 (동일 대상: 우측 사이드바 밀도) |
| `/` Gate | — | G1 pass / G2 pass / G3 pass |

| `/ui` Overall | ok | **good** (뒤집힘 ↑) |

**관찰**:
- **일관성 확보** — 같은 우측 사이드바가 vP-4와 vP-5에서 동일 이슈로 지적됨. Gate 체크 도입이 주의 대상 고정에 기여
- **Leniency 편향 발생** — Gemma가 이슈 2건을 지적하면서도 **G1/G2/G3 전부 pass**를 매김. 판정 기준이 "명시적 체크리스트"가 되자 이슈와 등급이 **분리**됨. Overall이 항상 good으로 수렴 — 새로운 hallucination 형태
- Gate 근거 서술이 대체로 **일반론**("적절한 명암 대비"·"글자 크기나 굵기를 통해") — 스크린샷 증거가 부족해도 pass 부여
- 이슈는 유지되었으나 Overall이 2 라우트 모두 good으로 상향 — "서술형 심각도 → gate 개수"는 일관성을 얻었지만 **엄격성을 잃음**

**남은 결함 / 다음 축 후보**:
1. **Gate leniency 편향** (새 결함) — Gate마다 fail 조건을 명시적으로 적어야 함. 예: "G1 fail: 본문 텍스트 어딘가에서 대비 부족 / 크기 부족 / 가려짐이 보이면 fail". 현재는 "대비가 있으면 pass"로 해석되어 fail 기준이 비어있음 (**vP-6 축 1순위**)
2. **이슈-게이트 연결 부재** — 주요 이슈와 게이트 판정이 논리적으로 연결되지 않음. "이슈 1번(밀도)이 있다면 G1이 fail이어야 하지 않나?"라는 내적 정합성 확인 조항 필요
3. **Gate 근거 구체성** — 근거 문장이 스크린샷 증거 없이 일반론. 구체 인용 요구를 gate 근거에도 확장

**수렴 판정**: vP-4의 "Overall 뒤집힘" 증상은 해소(동일 스샷 동일 이슈 지적) 됐으나, **새로운 편향(leniency)**이 만들어짐. **수렴 아님** — vP-6에서 leniency 해소 필요. 축이 바뀔 때마다 새 결함이 나오는 것은 **점수 시스템의 근본적 한계** 신호일 수 있음 (Phase 2 재설계 후보).

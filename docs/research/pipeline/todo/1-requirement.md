# Stage 1 — Requirement

**Pipeline**: `docs/research/pipeline/todo/` (단계별 관측 루프 baseline)
**Sample**: Todo 모바일 앱
**Viewport**: 375×812 (iPhone 기본)
**Created**: 2026-04-18

## 목적

단계별 산출물 스냅샷을 통해 "어느 단계에서 문제가 발생하는지" 격리하는 파이프라인 크리티크 루프의 **baseline 샘플**. 간단한 Todo 앱을 요구사항→데이터→컴포넌트→배치→조합 5단계로 내려가며 각 단계 아티팩트(JSON/DOM/스샷)를 저장한다.

## 기능 요구사항

1. **할 일 추가** — 화면 하단 입력창에 텍스트 입력 후 "추가" 버튼 또는 Enter로 목록에 추가
2. **할 일 완료 토글** — 리스트의 각 항목 체크박스를 눌러 완료/미완료 상태 전환. 완료된 항목은 회색 + 취소선
3. **할 일 삭제** — 각 항목 우측 삭제 버튼으로 제거
4. **빈 상태** — 목록이 비었을 때 "할 일이 없어요" 메시지 표시
5. **진행 요약** — 상단 헤더에 "완료 N / 전체 M" 표시

## 비기능 요구사항

- **Viewport**: 375×812 고정 (모바일 기준)
- **상호작용**: 키보드·터치 모두 동작 (ARIA OS 기반)
- **디자인**: `ax()` 축만 사용, `style={}` 금지
- **데이터**: `NormalizedData` + Command 패턴 (직접 setState 금지)
- **부품**: `src/interactive-os/ui/` 기존 완성품만 조립. 새 컴포넌트 금지
- **라우트**: `/todo`

## 화면 구조 (자연어)

```
┌───────────────────────────┐
│  Todo                     │ ← 헤더 (앱 이름 + "완료 N / M")
│  완료 1 / 3               │
├───────────────────────────┤
│  ☐ 우유 사기              │
│  ☒ 세탁물 찾기 (취소선)   │ ← 리스트
│  ☐ 이메일 확인            │
│                           │
│  (빈 영역)                │
├───────────────────────────┤
│  [새 할 일...      ][추가]│ ← 하단 입력바
└───────────────────────────┘
```

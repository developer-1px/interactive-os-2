# /improve — Birdseye

## 대상

`src/pages/birdseye/` — 코드베이스를 아키텍처 레이어 순서로 펼쳐보는 뷰. 좌측 TreeView(폴더 네비게이션) + 중앙 Kanban(폴더→컬럼, 파일→카드) + 플로팅 오버레이(코드 프리뷰 + 의존성 그래프).

## Jobs

| # | Job | 상황 |
|---|-----|------|
| J1 | 코드베이스 구조 파악 | "새 폴더에 들어왔는데, 여기 뭐가 있고 어떻게 엮여 있는지 빠르게 훑고 싶다" |
| J2 | 특정 파일의 영향 범위 확인 | "이 파일을 수정하면 어디가 깨질지 의존성을 확인하고 싶다" |
| J3 | 복잡도 핫스팟 발견 | "리팩토링 대상을 찾고 싶다 — 크고, 많이 참조되는 파일이 어디인지" |
| J4 | 레이어 의존 방향 검증 | "아키텍처 규칙(store→engine→axis→...→pages)을 위반하는 의존이 있는지 확인하고 싶다" |

## J1 Journey Map: 코드베이스 구조 파악

| Stage | Action (하는 것) | Thinking (생각) | Pain (아픈 것) | Wow (서비스가 대신?) |
|-------|-----------------|----------------|---------------|-------------------|
| 1. 진입 | birdseye 페이지를 연다 | "전체 구조부터 보자" | 첫 로딩 시 어떤 폴더가 선택되는지 URL에 없으면 첫 번째 폴더가 자동 선택되지만, 그게 내가 보고 싶은 곳인지 모른다 | — |
| 2. 폴더 선택 | 좌측 TreeView에서 폴더를 클릭한다 | "이 폴더 안에 뭐가 있지?" | TreeView가 디렉토리만 보여주므로 구조를 잘 반영하지만, **레이어 순서(store→engine→axis→...)가 아니라 알파벳순**이다. 아키텍처 의존 순서를 머릿속에 기억해야 한다 | ②구조: `_meta.yaml`의 order가 칸반 컬럼 순서에는 적용되지만, **좌측 TreeView 루트 레벨 정렬에는 적용되지 않는다**. 레이어 순서를 TreeView에도 반영하면 사용자가 기억할 필요 없다 |
| 3. 칸반 훑기 | 컬럼(하위 폴더)과 카드(파일)를 가로로 스크롤하며 읽는다 | "각 폴더에 뭐가 있고 얼마나 큰지 보자" | 컬럼이 많으면 **전체 폴더 수와 파일 수를 알 수 없다**. 끝까지 스크롤해야 전모가 보인다 | ②구조: 보드 헤더에 **폴더/파일 카운트 서머리**를 자동 표시하면 스크롤 전에 규모를 파악할 수 있다 |
| 4. 파일 프리뷰 | 카드에 포커스하면 250ms 후 플로팅 오버레이에 코드가 뜬다 | "이 파일이 뭐 하는 파일인지 빠르게 보자" | 오버레이가 **카드 우측에 고정 위치**로 떠서, 우측 컬럼의 카드를 볼 때 오버레이가 카드를 가린다 | ①자동화: 오버레이 위치를 포커스된 카드의 **반대쪽**(카드가 뷰포트 우측이면 왼쪽에 띄움)으로 자동 전환하면 가림 문제가 사라진다 |
| 5. 하위 폴더 탐색 | 카드가 디렉토리면 Enter/더블클릭으로 해당 폴더로 이동한다 | "더 깊이 들어가보자" | 깊이 들어간 후 **되돌아가려면 breadcrumb을 클릭**해야 한다. 키보드만으로 상위 폴더로 돌아가는 방법이 없다 | ①자동화: **Backspace 또는 Alt+Up**으로 상위 폴더 이동을 자동 바인딩하면 키보드 동선이 완성된다 |

## J2 Journey Map: 특정 파일의 영향 범위 확인

| Stage | Action (하는 것) | Thinking (생각) | Pain (아픈 것) | Wow (서비스가 대신?) |
|-------|-----------------|----------------|---------------|-------------------|
| 1. 파일 찾기 | Cmd+P로 QuickOpen을 열어 파일명을 검색한다 | "먼저 대상 파일을 찾자" | QuickOpen으로 파일을 선택하면 **코드 프리뷰만 뜨고, 칸반에서 해당 카드가 하이라이트되지 않는다**. 의존성 그래프도 로드되지 않는다 | ①자동화: QuickOpen 선택 시 해당 파일이 속한 폴더로 자동 이동하고, 카드에 포커스를 맞추면 의존성 하이라이트까지 자동으로 연결된다 |
| 2. 의존성 확인 | 카드에 포커스하면 오버레이에 "Used by N files" / "Depends on N files" 가 뜬다 | "이 파일을 누가 쓰고 있지?" | 의존 파일 목록은 보이지만, **칸반 위의 카드 하이라이트(highlightUp/Down)는 현재 보이는 폴더 내 카드만** 표시한다. 다른 폴더의 의존 파일은 오버레이 목록에서만 확인 가능하다 | ③표시 |
| 3. 의존 파일로 점프 | 오버레이의 dep 항목을 클릭한다 | "이 파일도 보고 싶다" | 클릭하면 **현재 칸반에 카드가 있으면** DOM focus, 없으면 상위 폴더로 이동한다. 그런데 이동 후 **원래 보던 파일로 돌아오는 방법이 없다** | ①자동화: dep 점프 시 **이전 위치를 스택에 push**하고, 뒤로가기(Alt+Left)로 복귀할 수 있게 하면 탐색 동선이 가역적이 된다 |
| 4. 영향 범위 판단 | importedBy 수와 파일 목록을 머릿속에서 종합한다 | "이 파일 건드리면 N곳이 깨지겠구나" | 의존성의 **깊이(직접 vs 간접)**가 구분되지 않는다. importedBy 10개 중 몇 개가 직접 import이고 몇 개가 re-export 경유인지 모른다 | ③표시 |

## 개선안

### O1: TreeView 루트 레벨이 알파벳순이라 아키텍처 레이어 순서를 머릿속에 기억해야 한다

- **Stage**: J1-2 (폴더 선택)
- **Pain**: `_meta.yaml` order가 칸반 컬럼에는 적용되지만 좌측 TreeView 루트 정렬에는 적용되지 않는다. 사용자가 `store → engine → axis → ...` 순서를 기억해야 한다.
- **Wow**: ②구조 — 루트 `_meta.yaml`의 order를 `buildNavStore`의 루트 레벨 정렬에도 적용하면, TreeView가 아키텍처 순서대로 나열된다.
- **변경**: `birdseyeTransform.ts:buildNavStore` — 루트 디렉토리 정렬 시 `_meta.yaml` order 배열을 인자로 받아 `sortDirs()` 재사용. `BirdseyeLayout.tsx` — navStore 빌드 시 kanbanOptions.columnOrder를 전달.
- **검증**: TreeView 루트 항목이 `_meta.yaml` order 순서와 일치하는지 확인. 알파벳순이 아님.

### O2: 칸반 보드 헤더에 전체 규모(폴더 수, 파일 수)가 없어서 끝까지 스크롤해야 전모를 안다

- **Stage**: J1-3 (칸반 훑기)
- **Pain**: 컬럼이 많을 때 전체 폴더 수와 파일 수를 파악하려면 가로로 끝까지 스크롤해야 한다.
- **Wow**: ②구조 — boardHeader breadcrumb 옆에 `N folders · M files` 카운트를 kanbanStore에서 자동 계산하여 표시.
- **변경**: `BirdseyeLayout.tsx` — kanbanStore의 relationships에서 컬럼 수(ROOT children)와 카드 수(전체 카드 entity)를 계산하여 boardHeader에 렌더링.
- **검증**: 폴더 선택 시 헤더에 카운트가 표시되고, extFilter 적용 시 카운트가 갱신됨.

### O3: 오버레이가 항상 카드 우측에 떠서, 우측 컬럼 카드 탐색 시 카드를 가린다

- **Stage**: J1-4 (파일 프리뷰)
- **Pain**: `calcOverlayPos`가 항상 `rect.right + gap`에 오버레이를 배치한다. 카드가 뷰포트 우측에 있으면 오버레이가 카드 위를 덮는다.
- **Wow**: ①자동화 — 카드의 뷰포트 위치를 판별하여, 카드가 뷰포트 중앙보다 우측이면 오버레이를 카드 좌측에, 좌측이면 우측에 자동 배치.
- **변경**: `BirdseyeLayout.tsx:calcOverlayPos` — `rect.left`가 `window.innerWidth / 2`보다 크면 `left = rect.left - overlayW - gap`으로 전환.
- **검증**: 우측 컬럼 카드에 포커스 시 오버레이가 카드 좌측에 뜨고, 카드가 가려지지 않음.

### O4: 깊이 탐색 후 상위 폴더로 키보드만으로 돌아갈 수 없다

- **Stage**: J1-5 (하위 폴더 탐색)
- **Pain**: 하위 폴더 Enter 진입 후 되돌아가려면 breadcrumb 마우스 클릭만 가능. 키보드 사용자의 동선이 끊긴다.
- **Wow**: ①자동화 — Backspace 또는 Alt+ArrowUp 키에 상위 폴더 이동을 바인딩. breadcrumb의 마지막에서 두 번째 segment의 id로 `selectFolder` 호출.
- **변경**: `BirdseyeLayout.tsx` — 보드 영역에 키보드 이벤트 핸들러 추가 (또는 Kanban의 keyMap 확장). Backspace 시 `breadcrumbs[breadcrumbs.length - 2]?.id`로 이동.
- **검증**: 폴더 진입 후 Backspace로 상위 폴더로 복귀. breadcrumb이 1단계일 때는 동작하지 않음(루트).

### O5: QuickOpen 파일 선택 시 칸반 연동이 없어서 의존성 하이라이트를 볼 수 없다

- **Stage**: J2-1 (파일 찾기)
- **Pain**: QuickOpen으로 파일을 선택하면 코드 프리뷰만 뜨고, 해당 파일이 속한 폴더로 칸반이 이동하지 않아 의존성 하이라이트가 동작하지 않는다.
- **Wow**: ①자동화 — QuickOpen 선택 시 파일의 부모 폴더를 자동 계산하여 `selectFolder` 호출 + 해당 카드에 focusedCardId 설정.
- **변경**: `BirdseyeLayout.tsx:handleQuickOpenSelect` — 파일 경로에서 부모 폴더를 추출, `selectFolder` 호출 후 `setFocusedCardId(`card:${filePath}`)` 설정.
- **검증**: QuickOpen으로 파일 선택 시 칸반이 해당 폴더로 이동하고, 카드가 포커스되며, 의존성 하이라이트가 표시됨.

### O6: dep 점프 후 원래 파일로 돌아오는 방법이 없어서 탐색 동선이 비가역적이다

- **Stage**: J2-3 (의존 파일로 점프)
- **Pain**: 의존 파일 클릭으로 다른 폴더에 이동하면, 이전에 보던 파일/폴더로 복귀할 수 없다. 가역적 동선 원칙 위반.
- **Wow**: ①자동화 — 폴더 이동 시 이전 `{folderId, focusedCardId}` 튜플을 히스토리 스택에 push. Alt+Left로 pop하여 복귀.
- **변경**: `BirdseyeLayout.tsx` — `navHistory` ref (스택 배열) 추가. `selectFolder` 호출 시 현재 상태를 push. Alt+Left 키에 pop+복원 바인딩.
- **검증**: dep 점프 → Alt+Left → 원래 폴더+카드 포커스 복원.

### O7: 컬럼 헤더에 totalLoc 데이터가 있지만 UI에 노출되지 않아 컬럼 간 복잡도 비교가 어렵다

- **Stage**: J3-2 (카드 비교)
- **Pain**: `buildKanbanStore`가 컬럼에 `totalLoc` 데이터를 이미 계산하지만, Kanban UI에 표시되지 않는다. 컬럼 간 규모를 비교하려면 카드를 하나씩 읽어야 한다.
- **Wow**: ②구조 — Kanban 컬럼 헤더에 `totalLoc`을 자동 표시. `maxColLoc` 대비 비율 바도 이미 Kanban.tsx에 계산되어 있으므로, 숫자만 추가하면 된다.
- **변경**: `Kanban.tsx` 또는 `Kanban.module.css` — 컬럼 헤더에 totalLoc 숫자를 렌더링 (이미 `maxColLoc` 계산 로직 존재).
- **검증**: 각 컬럼 헤더에 LOC 총합이 표시되고, 폴더 간 규모 비교가 스크롤 없이 가능.

### O8: 레이어 역방향 의존(위반)을 사용자가 경로를 읽고 수동으로 판별해야 한다

- **Stage**: J4-2 (파일별 의존 확인)
- **Pain**: 의존 파일 목록에 레이어 정보가 없다. 사용자가 경로에서 레이어를 추출하고 순서를 머릿속에서 대조해야 위반을 발견할 수 있다.
- **Wow**: ①자동화 — 의존 파일의 레이어를 자동 추출하고 현재 파일의 레이어와 비교. 역방향 의존이면 빨간색 마킹.
- **변경**: `BirdseyeLayout.tsx` — dep 목록 렌더링 시 레이어 순서 배열(CLAUDE.md의 `store→engine→axis→pattern→primitives→ui→pages`)과 대조. 역방향이면 `data-violation` 속성 추가. CSS에서 `[data-violation]` 스타일링.
- **검증**: axis 파일이 pattern을 import하는 경우 dep 목록에서 빨간색으로 표시됨. 정방향 의존은 일반 색상.

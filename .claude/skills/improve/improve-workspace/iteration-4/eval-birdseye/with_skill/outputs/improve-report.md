## J1 Journey Map: 아키텍처 레이어 구조 파악

| Stage | Action (하는 것) | Thinking (생각) | Pain (아픈 것) | Wow (서비스가 대신?) |
|-------|-----------------|----------------|---------------|-------------------|
| 1. 진입 | birdseye 페이지를 열고 사이드바에서 루트 폴더(src/interactive-os)를 선택한다 | "전체 구조를 보자" | | |
| 2. 레이어 순서 인식 | 칸반 컬럼들을 왼→오로 훑으며 "store → engine → axis → pattern → primitives → ui" 순서인지 머릿속에서 대조한다 | "이 컬럼 순서가 아키텍처 레이어 순서와 같은 건가?" | 컬럼 순서가 아키텍처 의존 순서를 보장하지 않는다. _meta.yaml이 없으면 알파벳순이므로 axis가 engine보다 앞에 온다. 사용자가 머릿속에 레이어 순서를 기억하고 눈으로 재배치해야 한다 | ①자동화: 아키텍처 레이어 의존 순서를 자동으로 결정하여 컬럼을 배치한다. 사용자가 순서를 기억할 필요가 없어진다 |
| 3. 레이어 간 경계 파악 | 컬럼 사이에서 "여기까지가 core고 여기서부터 ui" 같은 경계를 찾으려 한다 | "레이어 간 구분이 어디지?" | 모든 컬럼이 동일한 시각적 무게로 나열된다. 레이어 그룹 간 경계가 없어서 7개 레이어를 평면적으로 읽어야 한다 | ②구조: 레이어 그룹 간 시각적 구분(간격, 라벨, 색상 띠)으로 경계를 자연스럽게 드러낸다 |
| 4. 의존 방향 확인 | 특정 파일 카드에 포커스하여 dep highlight(초록/파랑)를 보고, "이 파일은 상위 레이어에서만 사용되는가?" 확인한다 | "의존 방향이 올바른가? 하위→상위 역전은 없나?" | 의존 방향(상위/하위)과 레이어 순서의 관계를 시각적으로 연결할 수 없다. highlight는 있지만 '왼쪽으로 가는 의존 = 역전'이라는 것을 사용자가 추론해야 한다 | ②구조: 의존 화살표가 레이어 순서(좌→우)를 기준으로 정방향/역방향을 색으로 구분한다. 레이어 역전을 즉시 인식할 수 있다 |

## J2 Journey Map: 특정 모듈의 의존 관계 추적

| Stage | Action (하는 것) | Thinking (생각) | Pain (아픈 것) | Wow (서비스가 대신?) |
|-------|-----------------|----------------|---------------|-------------------|
| 1. 파일 찾기 | 사이드바에서 폴더를 클릭하거나 Cmd+P로 파일을 검색한다 | "useAria.ts가 어디 있더라?" | | |
| 2. 포커스 | 칸반에서 해당 카드를 찾아 키보드/마우스로 포커스한다 | "이 파일이 뭘 의존하고, 누가 이걸 쓰지?" | 카드가 많으면 스크롤하며 눈으로 찾아야 한다. QuickOpen은 있지만 결과가 코드뷰어에만 연결되고 칸반 카드 포커스로 연결되지 않는다 | ①자동화: QuickOpen 결과가 해당 카드로 칸반 포커스를 이동시키고, 필요시 폴더도 자동 전환한다 |
| 3. dep 확인 | 오버레이의 dep list에서 "Used by N files", "Depends on N files"를 열어 파일 목록을 읽는다 | "이 중에 내가 건드릴 파일이 있나?" | dep 목록이 파일명만 나열된다. 현재 칸반에 보이는 파일인지, 다른 폴더에 있는 파일인지 구분이 안 된다 | ③표시: dep 목록에서 현재 칸반에 보이는 파일은 볼드, 다른 폴더는 경로 표시 |
| 4. dep 따라가기 | dep 목록의 파일을 클릭하여 해당 파일로 점프한다 | "이 의존성을 따라가 보자" | 다른 폴더의 파일을 클릭하면 폴더가 전환되면서 이전 맥락(어디서 왔는지)을 잃는다. 뒤로가기가 없다 | ①자동화: 폴더 탐색 히스토리를 유지하여 뒤로가기(Alt+Left)로 이전 위치로 복귀할 수 있다 |
| 5. 영향 범위 판단 | dep highlight(초록=importedBy, 파랑=imports)를 칸반 전체에서 눈으로 확인한다 | "영향 범위가 이 폴더 안에 국한되나, 아니면 넓게 퍼져있나?" | 현재 폴더 밖의 의존 관계는 보이지 않는다. 칸반은 선택된 폴더만 보여주므로 cross-folder 영향 범위를 파악하려면 머릿속에서 조합해야 한다 | ②구조: 오버레이 dep 목록에 폴더별 그룹핑은 이미 있다. 요약 한 줄("3 folders, 12 files affected")이면 범위 감각을 준다 |

### 공통 원인

이 Pain들이 동시에 존재하는 이유: **birdseye가 "아키텍처 레이어 순서"를 핵심 가치로 표방하면서도, 실제 구현은 파일시스템 트리를 칸반으로 시각화하는 것에 머물러 있다.** 레이어 모델(store -> engine -> axis -> pattern -> primitives -> ui)이 시스템에 내재화되어 있지 않고, 사용자의 머릿속에만 존재한다. 따라서 순서, 경계, 방향, 위반 등 레이어 기반 판단은 모두 사용자에게 전가된다.

---

### Feature 1: Layer-Aware Kanban (레이어 인식 칸반)

**칸반이 아키텍처 레이어 모델을 내재화하여, 컬럼 순서/그룹 경계/의존 방향을 자동으로 결정하고 표현한다.**

- 이 feature가 해결하는 Pain: P1, P2, P3, P7
- 제품이 어떻게 바뀌는가: "파일시스템을 칸반으로 보는 도구" -> "아키텍처 레이어를 칸반으로 보는 도구"
- 사용자의 행동이 어떻게 바뀌는가: "컬럼 순서를 머릿속으로 재배치하며 읽음" -> "좌에서 우로 읽으면 그것이 곧 의존 순서"

#### 변경

- `src/pages/birdseye/birdseyeTransform.ts` — `buildKanbanStore`에 레이어 순서 맵(CLAUDE.md의 `store → engine → axis → pattern → primitives → ui → pages`) 내장. `_meta.yaml`이 없어도 폴더명 기반 레이어 순서 자동 결정
- `src/pages/birdseye/birdseyeTransform.ts` — 컬럼 데이터에 `layerGroup` 필드 추가 (e.g. "core", "binding", "surface"). 같은 그룹 간 간격 축소, 그룹 간 간격 확대
- `src/interactive-os/ui/Kanban.tsx` 또는 `BirdseyeLayout.module.css` — 레이어 그룹 간 시각적 구분 (넓은 gap + 그룹 라벨)
- `src/pages/birdseye/BirdseyeLayout.tsx` — dep highlight에 "역방향 의존" 표시 추가: 좌측(하위 레이어)으로 향하는 dep은 경고색(destructive)으로 표시
- `src/pages/birdseye/birdseyeTransform.ts` — 카드 데이터에 `layerViolation: boolean` 필드: check:deps 로직 재사용하여 위반 파일 badge

#### 검증

- `_meta.yaml` 없는 폴더에서도 컬럼이 레이어 의존 순서로 정렬되는지 확인
- 레이어 역전 의존(예: store가 ui를 import)이 destructive색으로 하이라이트되는지 확인
- 레이어 그룹 경계가 시각적으로 구분되는지 스크린샷 확인

### Feature 2: Navigation History (탐색 히스토리)

**폴더 탐색, dep 점프, QuickOpen을 하나의 탐색 히스토리 스택으로 통합하여, 브라우저처럼 앞/뒤로 이동할 수 있게 한다.**

- 이 feature가 해결하는 Pain: P4, P5, P8
- 제품이 어떻게 바뀌는가: "한 폴더를 보는 정적 뷰" -> "코드베이스를 탐색하는 내비게이션 도구"
- 사용자의 행동이 어떻게 바뀌는가: "dep를 따라가다 길을 잃고 사이드바로 돌아감" -> "Alt+Left로 이전 위치로 돌아옴. dep 따라가기가 자연스러운 탐색 흐름이 됨"

#### 변경

- `src/pages/birdseye/BirdseyeLayout.tsx` — 탐색 히스토리 스택 추가: `{ folderId, focusedCardId }[]` + currentIndex. 폴더 선택/dep 점프/QuickOpen 모두 히스토리에 push
- `src/pages/birdseye/BirdseyeLayout.tsx` — Alt+ArrowLeft(뒤로)/Alt+ArrowRight(앞으로) 키바인딩 등록. 브라우저 표준과 동일한 UX
- `src/pages/birdseye/BirdseyeLayout.tsx` — QuickOpen 결과 선택 시 해당 파일의 부모 폴더로 selectFolder + 칸반에서 해당 카드를 자동 포커스
- `src/pages/birdseye/BirdseyeLayout.tsx` — 코드 뷰어의 dep list 클릭이 폴더 전환 + 카드 포커스까지 연결 (현재는 폴더 전환만)

#### 검증

- dep list에서 다른 폴더의 파일 클릭 -> 폴더 전환 -> Alt+Left -> 이전 폴더+카드 위치 복원 확인
- QuickOpen으로 파일 선택 -> 해당 칸반 카드에 포커스 + 오버레이 표시 확인
